## 1. 暴露问题的实测现象(可复现)

建库方向:`in-context learning`(min-year 2025,brain=claude)。产出 73 篇主库,但:

1. **接收状态双向错标**:73 篇里仅 ~21 篇真正接收;54 篇是 ICLR 2026 OpenReview **被拒/撤稿投稿**却标 `venue=ICLR`。反向:TMLR 著名论文(cit=348)被标 `ICLR/2025+status=Reject`;已在 ACL Anthology(`2026.eacl-11`)发表的 EACL 论文被标 `status=Reject`。
2. **方向拆解注入无关噪声词**:`topic.yaml: source_filter_terms` 出现 `latent communication / latent multi agent / kv cache communication / state delta trajectory / hybrid latent text` 等与 ICL 无关的词;`scaling laws`(召回 267)、`bayesian inference`(召回 123)等通用词被当独立宽锚点。
3. **首跑莫名失败**:`needs_rule_repair`(exit 5),实际只是复核批次预算默认值太小。

## 2. 根因定位(代码级)

### A. 多源元数据融合无源优先级 —— 双向错标的真凶(最严重)

| 层 | 文件:函数 | 问题 |
| --- | --- | --- |
| 源 | `discovery.py: paperlists_item_to_raw()` (~820-857) | 直接取 OpenReview 投稿的 `status`(Reject/Withdraw/Poster)与参数 `venue`;`paperlists`(`papercopilot/paperlists`)是**混合全量投稿(含拒稿)与发表论文**的池子 |
| 融合(罪魁) | `normalize.py: merge_paper()` (~321-346) | 第 ~343-344 行对 `status`/`venue`/`decision` **只做"空值填充",无源可信度优先级**;ACL Anthology(权威)与 paperlists 合并时谁胜出取决于处理顺序 |
| 去重 | `normalize.py: identity_keys()` (~288-318) | 能匹配同一篇,但 `paperlists_item_to_raw` 在 `site` 指向 anthology 时未提取 `acl_id`,跨源链接偏弱 |
| 范围过滤 | `scope.py: paper_matches_publication_scope()` (~319-341) | 只看单一 `venue`,无法从 `source_records` 还原真实发表 venue |

### B. 方向拆解注入噪声词 + 通用词无护栏

| 文件:函数 | 问题 |
| --- | --- |
| `auto/plan.py: _coverage_axis_aliases()` (~291-408) | 当 `latent_axis AND (agent_axis OR multi_agent_axis)` 时**无条件 add 一串硬编码 multi-agent 词**(~364-376)。本次 direction 的 **out-of-scope 条款**写了"…or **agent** online adaptation",axis 正则 `_blob_has_any(blob,…)` **扫了整段(含排除条款)**→ `implicit` 命中 latent、`agent` 命中 agent → 误触发。**排除条款被当成正向信号 + 硬编码跨域词** |
| `auto/plan.py: recall_terms_for_plan()` (~450-497) / `_is_generic()` (~153-162) | 接受 brain 输出的 hints/discriminator 不做"过泛"校验;`_is_generic()` 只挡停用词/单 token,挡不住 `scaling laws`、`bayesian inference` 等多词 meta 术语 |
| `discovery.py: topic_match_decision()` (~622-650) | 源级匹配是**裸子串**,任一 `source_filter_term` 出现即放行 → 通用词制造大量假阳(267 / 123) |

### C. 预算/门控 oversell 失败(附我先前说法的更正)

- **更正**:首跑失败**不是**"discovery 把 `--max-remote-calls` 吃光饿死复核"。`max-remote-calls` 只记 discovery 的 HTTP 调用;brain 复核是独立资源。
- **真因**:`auto/quality_gate.py: diagnose_review_queue()` (~43-156) 的 `capacity_for_rule = max(1000, batch×max_batches×2)`,默认 `weak_max_batches=20` → `capacity=1000`;pending 1478 > 1000 → `weak_queue_too_large(severity=rule_repair)` → `orchestrator.py: run_auto_build()` (~742) **在 score_papers 之前 early-return,exit 5**。
- **验证**:`--weak-max-batches 65` → `capacity=3250>1478` → 放行,正常产出。决定成败的是 `weak-max-batches`,与 `max-remote-calls` 基本无关。状态名把"参数太小"包装成了"要改规则"。
- **附带**:`stages.py: stage_score_papers()` (~799-827) `rerank_top_k=max_batches*batch_size`,只有 embedding top-k 进 brain,其余靠 embedding+metadata 融合 → `brain_missing_scores` 警告(语义上既是 feature 又是 warning)。

## 3. 改进方案(分阶段 · 任务清单 · 状态)

> 状态图标:⬜ 未开始 · 🟦 进行中/部分 · ✅ 完成 · ⏸ 暂缓
> **实现进度与变更日志见同目录 [`实施进度.md`](./实施进度.md)。本节状态已与之同步(2026-06-19)。**

### P0 — 速修(localized、低风险,先做)

- ✅ **A1 merge 源优先级**:**实际实现**改为在 `normalize.deduplicate_papers()` 收尾处做(`_finalize_venue` 按源可信度选 venue;`_finalize_publication_status` 派生发表状态),比改 `merge_paper` 逐字段 provenance 更简、且**顺序无关**。覆盖 `venue` + 新增 `publication_status`;`decision/track/year` 暂未纳入(按需再扩)。
- ✅ **B1 axis 检测只扫 in-scope**:`plan.py: _in_scope_text()` 截断 out-of-scope 段,在 `_coverage_axis_aliases` 两处调用前应用。
- ✅ **B2 去硬编码桥接词**:**决策(取舍)**——不删除作者有意的跨轴桥接词,改为只在 in-scope 触发(由 B1 实现),既修误注入又保留特性。
- ✅ **C1 门控去 oversell + 自适应批次**:`weak_queue_too_large` 降为 `budget`(并移出 `RULE_REPAIR_WARNINGS`);orchestrator 在门控前自动提批(needed≤80 提到 needed,记 `weak_budget_autoraised`)。沿用现有 `partial_due_to_budget` 状态名 + `recommended_max_batches` 提示(未新造 `needs_bigger_review_budget`)。

### P1 — 结构性增量

- ✅ **B3 通用词护栏**:`plan.py: _DENY_STANDALONE_RECALL_TERMS` + 在 `recall_terms_for_plan` 末尾过滤;topic 复合词不受影响。
- ⏸ **B4 召回词体检**:暂缓。需 plan 阶段联网、测试不稳;B3 + 现有 `generic_anchor_dominates` 门已覆盖观测问题。
- ✅ **A2 接收状态一等公民**:`scope.py` 加 `acceptance ∈ {accepted_only, accepted_or_preprint(默认), any}` 门,按 `publication_status` 过滤。**未做** `venue_submitted/venue_published` 双字段拆分(`publication_status` + 源优先级 venue 已够用)。
- 🟦 **A3 arXiv 作为合法 venue(部分)**:scope 侧已让 preprint 经 `include_preprints` 放行、被拒投稿不冒充接收。**未做** discovery 侧"保留 arXiv 链接并与 OpenReview/anthology 记录链接"——所以"被拒但有较新 arXiv 版"目前仍可能只剩 OpenReview 壳。该剩余项与下面 C2/T3 的链接改造重叠,留待一起做。

### P2 — 体验 / 可解释

- ⏸ **C2 加预算 resume**:暂缓。C1 自动提批已消除常见场景;干净 resume 是状态机较大改动。
- 🟦 **C3 进度与状态文案(部分)**:✅ `batch i/N` 真实总数(score_papers + resolve_boundary)。**未做**:`brain_missing_scores` 拆成 info/warning、final_summary 状态码附人话(C1 已给门控的可操作提示)。
- ⬜ **预算分账文档化**:未做(轻量文档项)。

### T3 — 可选大改(流程重构)

- ⏸ **实体解析 + 元数据融合层**:按强 ID(DOI/arXiv/ACL/OpenReview)聚类成 work;每字段按源可信度 + 证据选值并保留 provenance;`publication_status` 由"是否出现在权威发表索引"决定,而非取自任一源裸字段。
  - 收益:A 类错误从根消失;支持"只要接收 / 接收+preprint / 全部"分层导出。
- ⏸ **召回可解释 + 假阳率报告**:QA 报告给"按召回词的假阳率",前置暴露 B 类过泛。
- ⏸ **brain 复核增"发表证据抽取"**:与实体层发表状态交叉校验。

> 建议顺序:**P0 全部 → A2/A3(接收状态结构化) → 视情况 T3**。A 类的实体/融合层是最值得做的结构性投资。
